Project Overview

▼

The Data Center Consensus GIS Model is a production-ready data pipeline that integrates multiple external vendor data sources with Meta's internal canonical datacenter inventory. The goal is to create a unified, validated view of global datacenter facilities for infrastructure planning and competitive intelligence.

Project Objectives

  • 📥 Ingest 6 external vendor sources + Meta canonical data
  • 🔄 Harmonize into standardized "gold" feature classes
  • ✅ Validate using Meta canonical as ground truth
  • 📊 Benchmark vendor spatial and capacity accuracy
  • 🔁 Produce repeatable, documented workflows

Methodology: Apples-to-Apples Comparison

Ground Truth: Meta Canonical IT Load (276 buildings, 10,968.61 MW total)

Matching Method: Closest spatial match per building, deduplicated to 1:1

FactorApproachWhy It Matters
GranularityBuilding-level matches onlyAvoids apples-to-oranges campus vs building comparisons
Capacity DefinitionIT load vs IT load (no PUE adjustment)Both Semi and DCH report IT capacity directly
Time AlignmentUse mw_2023 (not 2024+)Meta data reflects ~2023 state; future forecasts add variance
DeduplicationKeep closest match per building/sourcePrevents 1:many spatial join inflation
Build Status FilterComplete Builds only for MAPEActive/Future builds have inherent uncertainty

Methodology

▼

Detailed methodology documentation is maintained in separate files for in-depth reference. Click links below to access full documentation.

UCID Clustering

Purpose: Source-agnostic spatial clustering for campus identification

Approach: Geospatial clustering + company matching to generate human-readable IDs (e.g., META-ALTOONA-01)

Documentation: UCID_DESIGN.md

Meta Deduplication

Purpose: Aggregate Meta canonical data from suite → building → campus levels

Approach: Dissolve by building_key with MULTI_PART geometry, sum IT loads

Documentation: META_CANONICAL_WORKFLOW.md

Spatial Accuracy Testing

Purpose: Benchmark vendor coordinate accuracy against Meta ground truth

Approach: Haversine distance calculation, recall %, threshold analysis (100m, 500m, 1km)

Documentation: PIPELINE_DOCUMENTATION.md (Section 4)

Capacity Accuracy Testing

Purpose: Validate vendor MW estimates against Meta actual IT load

Approach: MAPE calculation, PUE adjustment analysis, outlier detection

Documentation: CAPACITY_FIELD_DEFINITIONS.md

Company Standardization

Purpose: Normalize 3,000+ company names to canonical forms

Approach: 3-field structure (source, clean, filter) with hyperscaler priority list

Documentation: migrate_company_fields_v2.py

Schema Design

Purpose: Define optimal field structure for consensus model

Approach: Compared 4 schemas, identified 14 fields to add, 9 to remove

Documentation: SCHEMA_COMPARISON_ANALYSIS.md

Field Lineage

Purpose: Track every field from raw source through pipeline to XB layer

Approach: Source-to-gold mapping tables, aggregation rules, unit conversions

Documentation: MASTER_FIELD_MAPPING.html
