3. Distance Calculation: Why Haversine Matters

▼

The Problem with Euclidean Distance

flowchart LR subgraph euclidean[Euclidean ❌] E1[Flat X/Y math] E2[1° varies by latitude] end subgraph examples[Longitude = 1°] P1[Equator: 111 km] P2[45°N: 78 km] P3[89°N: 2 km] end E1 --> E2 E2 --> P1 E2 --> P2 E2 --> P3

The Solution: Haversine Distance

flowchart LR subgraph haversine[Haversine ✅] H1[Great-circle distance] H2[Actual meters returned] H3[500m = 500m everywhere] end H1 --> H2 --> H3

Visual Comparison

EUCLIDEAN (Planar) ❌

√(Δx² + Δy²)
Treats Earth as flat

HAVERSINE (Spherical) ✅

2R · arcsin(√a)
Accounts for curvature

Accuracy for UCID Matching

Distance Haversine Error* For 250m Match For 1000m Match
100 m< 0.1 m✅ Negligible✅ Negligible
250 m< 0.8 m✅ Negligible✅ Negligible
500 m< 1.5 m✅ Negligible✅ Negligible
1 km~ 3 mN/A✅ Negligible

*Error vs geodesic (ellipsoid) calculation. Haversine assumes perfect sphere.

Bottom Line: For UCID matching at 250m-1000m scales, Haversine error is <3 meters — completely acceptable for campus clustering.

🌐 Coordinate System: WGS 1984 (GCS)

▼

This pipeline uses WGS 1984 (EPSG:4326) — a Geographic Coordinate System (GCS), not a Projected Coordinate System (PCS).

AspectGCS (WGS 1984) ✅PCS (e.g., Web Mercator)
WKID43263857 (Web Mercator)
UnitsDegrees (lat/lon)Meters
Coverage✅ Global⚠️ Often regional or distorted
Distance CalcNeed Haversine/GeodesicCan use Euclidean
Your Use Case✅ Correct choiceWould distort at high latitudes

Why WGS 1984 is Right for This Pipeline

🌎 Global Coverage

AMER, EMEA, APAC — no projection distortion anywhere

📍 GPS Compatible

Matches raw GPS coordinates from all sources

🌐 Web GIS Native

Standard for web mapping and data exchange

📐 Haversine Ready

Works directly with our distance calculations

Code Reference

// From import_dch_csvs.py and import_meta_canonical_v3.py
coordinate_system = arcpy.SpatialReference(4326)  // WGS84
