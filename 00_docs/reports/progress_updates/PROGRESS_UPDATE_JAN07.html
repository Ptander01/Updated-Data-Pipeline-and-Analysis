1. Matching Strategy Evolution

Multiple approaches were explored to ensure precise matching of Essential sites:

ApproachMethodResult
❌ Spatial Join 5km radius matching Risk of matching wrong campus in same city
❌ Company + City Attribute match on company slug Too many false positives (e.g., all AWS Atlanta)
❌ Cluster ID Match on SA cluster format Format mismatch: AWS_Atlanta_1 vs aws|atlanta|1
✅ SA Unique_ID (UUID) Exact match on source_unique_id 127/129 matched (98.4%)

Why UUID Matching?

The user provided exact SA Unique_IDs from a GSheet containing all 129 building-level records. This ensures:

  • No false positives: Exact UUID match, not heuristic
  • Building-level precision: Matches individual buildings, not just campuses
  • Pipeline rollup: Essential flag automatically aggregates to campus level

2. Pipeline Integration

The is_essential flag is set at building level and automatically rolls up through the pipeline:

  • integrate_essential_by_uid.py Created
    Matches 129 SA Unique_IDs to gold_buildings_full, sets is_essential=1
  • campus_rollup_new.py Updated
    Added is_essential aggregation: MAX = if ANY building is essential, campus is essential
  • create_xb_combined_layer.py Updated
    Added is_essential to UNIFIED_SCHEMA for buildings and campuses

3. UCID Rollup Behavior

127 Buildings → 73 Campuses

Essential buildings roll up to fewer campuses because UCID grouping is source-agnostic. Multiple buildings at the same physical location (potentially from different sources) share the same UCID and aggregate to a single campus record.
