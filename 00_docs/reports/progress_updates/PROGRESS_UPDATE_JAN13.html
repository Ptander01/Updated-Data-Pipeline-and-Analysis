🔧 Session 23 — Year MW Field Fix CRITICAL FIX

🐛 The Problem

After ingestion, validation showed year fields (mw_2023-mw_2032) were only 7-25% populated, but the source Excel showed 40-77%. We were losing 70% of the year-over-year MW forecast data!

Root Cause Analysis

  1. The SA pipeline was creating duplicate year columns ('2023' AND '2023.0')
  2. Pandas reads numeric Excel headers as floats (2023 → "2023.0")
  3. Ingestion used: row.get('2023') or row.get('2023.0')
  4. When '2023' contained '0' (string), it was truthy, so '2023.0' was never checked
  5. The actual MW values were in '2023.0' columns — lost!

The Fix

Added two new functions to semianalysis_pipeline.py:

def normalize_column_names(df): """Convert '2023.0' → '2023' during extraction""" # Also marks remaining duplicates with _dup suffix def merge_duplicate_columns(df): """Merge duplicate columns by taking positive values""" # Combines data from both column versions
