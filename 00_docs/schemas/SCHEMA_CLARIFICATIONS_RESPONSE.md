**Answer:** ✅ **YES — The UCID system is designed for exactly this purpose.**

- **UCID Format:** `UCID-{REGION}-{SEQUENCE}` (e.g., `UCID-AMER-00142`)
- **Purpose:** Source-agnostic identifier that links campus records across all vendors

**Recommendation:**

| `ucid` | Campus | Generated by `generate_ucid_clusters.py` |
| `unique_id` | Building | Keep as `{SOURCE}_{source_unique_id}` for building-level records |

The `assign_ucid_to_gold.py` script already adds `ucid` field to both `gold_campus_full` and `gold_buildings_full`.

## 5️⃣ CAPACITY SPACE — building_sqft vs whitespace_sqft

**Difference:**

| Field | Definition | Use Case |
|-------|------------|----------|
| `facility_sqft` (building_sqft) | Total building footprint | Overall facility size |
| `whitespace_sqft` | Raised floor / deployable space | **Available** space for IT equipment |

**Both are necessary** — they measure different things:
- A 500,000 sqft building might only have 200,000 sqft of whitespace
- Whitespace is the "usable" space for servers

**Recommendation:** ✅ Keep both fields.

## 7️⃣ STATUS & LIFECYCLE — building_type vs owned_leased

**Your Question:** Is `building_type` the same as `owned_leased`?

**Answer:** ❌ **No, they're different concepts:**

| Field | Values | Describes |
|-------|--------|-----------|
| `owned_leased` | "Owned", "Leased" | **Ownership model** — who owns the building |
| `building_type` | "Hyperscale", "Colocation", "Enterprise", "Edge" | **Facility classification** — what type of DC |

**Examples:**
- Meta Altoona: `owned_leased = "Owned"`, `building_type = "Hyperscale"`
- Meta in Vantage facility: `owned_leased = "Leased"`, `building_type = "Hyperscale"` (or could be "Colocation")

**Recommendation:**
- ✅ Keep `owned_leased` — Already populated from Meta Canonical
- 🤔 `building_type` — Nice to have, but may be redundant with `company_clean_filter` (Hyperscaler vs Colo)

If you want to skip `building_type`, that's fine — the company filter provides similar segmentation.
